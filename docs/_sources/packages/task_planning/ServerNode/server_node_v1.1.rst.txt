Documentação do Server Node (Atual v1.1)
========================================

O ``ServerNode`` v1.1 representa uma evolução significativa na inteligência do robô.
Além de orquestrar a navegação e manipulação via **Behavior Trees**, esta versão integra verificação cinemática avançada e monitoramento de caminho em tempo real através de acesso direto à memória (Shared Pointers).

.. note::
   **Arquitetura Híbrida:** O nó continua sendo **Multi-Threaded**, mas agora atua como um *Container* para vários outros componentes (`Reachability`, `ObstacleGraph`, `IKValidator`), instanciados via composição para eliminar a latência de comunicação ROS.

---

1. Novidades da Versão 1.1
--------------------------

A principal mudança nesta versão é a transição de uma abordagem puramente "reativa" para uma abordagem "deliberativa com verificação contínua".

* **Validação Cinemática (IsReachable):** Antes de navegar, o robô verifica se a posição de destino permite fisicamente que o braço alcance o objeto (IK Check).
* **Monitoramento de Caminho (IsPathClear):** Enquanto o robô pensa ou executa tarefas, o nó verifica se o caminho calculado anteriormente foi obstruído por novos obstáculos dinâmicos.
* **Grafo de Obstáculos Compartilhado:** O mapa de obstáculos não é mais recebido apenas por tópicos, mas acessado via ponteiro compartilhado do nó :doc:`Obstacle Graph v1.0 <../../navigation/SharedObstacleGraph/shared_obstacle_graph_v1.0>` para consultas de complexidade O(1).
* **Análise de Alcançabilidade Projetada:** Essa análise agora é feita via ponteiro compartilhado pelo nó :doc:`Projected Reachability Analysis v1.0 <../../manipulation/ProjectedReachabilityAnalysis/projected_reachability_analysis_v1.0>`.

3. Detalhamento dos Nós da Behavior Tree
----------------------------------------

Abaixo descrevemos a implementação lógica de cada nó registrado na fábrica da BT.

Condições de Verificação (Guards)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

**IsPathClear (Novo na v1.1)**
Esta condição é crucial para a segurança dinâmica. Ela verifica se o caminho de navegação atual (`last_no_filter_calculated_path_`) colide com algum obstáculo recém-detectado.

* **Funcionamento:**
  1. Obtém um *snapshot* (cópia leitura) do mapa atual via `obstacle_graph_node`.
  2. Itera sobre todos os pontos do caminho planejado.
  3. Se algum ponto do caminho coincidir com um obstáculo no mapa, retorna **FAILURE**.
  4. Em caso de falha, aciona imediatamente `cancel_controller_goal()` para parar o robô.

.. literalinclude:: ../../../../../docs_central/legacy_src/task_planning/server_node_v1.1.cpp
   :language: cpp
   :start-after: // DOC-START: BT_IsPathClear
   :end-before: // DOC-END: BT_IsPathClear

**IsReachable (Novo na v1.1)**

Verifica se o alvo é alcançável pelo braço robótico a partir da posição atual considerando as colisões do Moveit.

* **Lógica:**
  1. Consulta o `reachability_node` para obter um anel de posições 2D viáveis ao redor do objeto.
  2. Utiliza o `ik_validator_node` para testar soluções de Cinemática Inversa (IK) nessas posições, considerando os obstáculos 3D atuais.
  3. Se a posição atual do robô for válida, retorna **SUCCESS**.
  4. Se a posição atual for ruim, mas existir uma posição válida próxima, calcula a pose de ajuste e retorna **FAILURE** (forçando a árvore a executar uma ação de navegação para o `adjustment_pose`).

5. Implementação das Actions e Comparativo (v1.0 vs v1.1)
---------------------------------------------------------

A comunicação assíncrona com os servidores de ação (Path Planner, Controller e Manipulação) sofreu refatorações importantes para garantir a integridade dos dados em um ambiente *multithreaded*.

Action de Planejamento de Caminho (Path Planning)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

A principal diferença arquitetural na v1.1 é a **remoção do Callback de Feedback**.
Na v1.0, o nó dependia do feedback do servidor para saber se um recálculo estava ocorrendo. Na v1.1, a verificação de obstrução foi movida para a Behavior Tree (nó `IsPathClear`), tornando a chamada de ação mais limpa e atômica.

**v1.1 (Atual): Thread-Safe e Sem Feedback**

Observe o uso intensivo de ``std::lock_guard`` para proteger os ponteiros dos Goals e os vetores de caminho. Isso previne "race conditions" quando a BT cancela e reinicia tarefas rapidamente.

.. literalinclude:: ../../../../../docs_central/legacy_src/task_planning/server_node_v1.1.cpp
   :language: cpp
   :start-after: // DOC-START: send_path_goal
   :end-before: // DOC-END: send_path_goal

.. note::
   **Diferença Crítica v1.0 vs v1.1:**
   Na **v1.0**, o código configurava ``send_goal_options.feedback_callback``. Isso criava uma dependência complexa onde o servidor de planejamento podia cancelar o controlador de base remotamente.
   Na **v1.1**, essa lógica foi removida. O ``ServerNode`` agora apenas recebe o caminho final. A responsabilidade de verificar colissões dinâmicas passa para o nó ``IsPathClear``, desacoplando o planejamento da execução.

**Callbacks de Resposta (v1.1)**

O tratamento do resultado na v1.1 agora armazena duas versões do caminho: com e sem filtro de inflação, permitindo validações mais precisas de *Reachability*.
