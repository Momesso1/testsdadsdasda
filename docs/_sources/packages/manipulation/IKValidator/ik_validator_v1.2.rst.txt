ik_validator.cpp (v1.2 - Atual)
====================================================

O nó ``IKValidator`` v1.2 representa uma evolução arquitetural em relação à v1.0, introduzindo **memória de estado**.
Enquanto a versão anterior operava de forma puramente funcional (entrada -> cálculo -> saída), a v1.2 mantém o contexto da última decisão válida.

Isso habilita o uso de **Behavior Trees Reativas**, permitindo que o robô valide continuamente (a 50Hz ou mais) se a decisão tomada no passado ainda é segura no presente, sem incorrer no custo computacional de recalcular todo o planejamento.

.. note::
   **Conceito Chave:** A persistência permite transformar um cálculo custoso (Busca de Base) em uma verificação barata (Monitoramento de Base).

---

1. Inicialização e Configuração
-------------------------------

O construtor e o método ``delayed_init`` preparam o ambiente de simulação do MoveIt.

* **Parâmetros ROS:**
    * ``group_name``: Define qual grupo de juntas controlar (padrão: "panda_arm").
    * ``max_reach_3d``: Raio máximo de busca para descartar alvos inalcançáveis antes do IK.
* **Scene Monitor:** Inicializa o ``PlanningSceneMonitor`` para manter uma cópia interna do ambiente do robô atualizada em tempo real.
* **Virtual Joint:** Detecta automaticamente se o robô possui juntas virtuais (ex: base omnidirecional ou trilho) para incluí-las no cálculo da Cinematica Inversa.

---

2. O Cálculo Principal (Find Best Base)
---------------------------------------

A função ``find_best_base_position`` é o "cérebro" do nó. Ela é chamada quando o robô precisa decidir **onde parar** para pegar um objeto.

Esta função é computacionalmente intensiva, pois:
1.  Recebe uma lista de dezenas de posições candidatas.
2.  Filtra posições inválidas no mapa 2D (obstáculos de navegação).
3.  Cria uma cena isolada no MoveIt.
4.  Configura a matriz de colisão (ACM) para permitir tocar no objeto alvo.
5.  Itera sobre os candidatos executando o Solver de IK (Cinemática Inversa).

**A Inovação da v1.2:**
Ao final do processo, se uma solução é encontrada, ela é **armazenada nas variáveis membro da classe** (`selected_ik_position`, `last_target`, etc.). Isso cria um "snapshot" da decisão para uso futuro.

3. Validação Multi-Alvo (Find Valid Targets)
--------------------------------------------

A função ``find_valid_targets_from_base`` resolve o problema oposto: **"Se o robô estiver parado aqui, quais destes 10 objetos ele consegue alcançar?"**

Diferente da função anterior (que busca uma base para um alvo), esta função:
1.  Fixa a posição da base do robô.
2.  Itera sobre uma lista de poses de objetos (targets).
3.  Utiliza um filtro de distância euclidiana simples (`max_reach_3d`) para descartar objetos muito distantes antes de tentar o IK.
4.  Retorna uma lista filtrada apenas com os objetos alcançáveis.

*Útil para otimização de tarefas de picking onde o robô deve pegar múltiplos itens sem mover a base.*

---


4. Revalidação Reativa (Is Still Reachable)
-------------------------------------------

Esta é a função mais crítica para a responsividade do sistema. Projetada para ser executada dentro de um nó **Condition** da Behavior Tree (ex: ``<IsStillReachable/>``), ela roda em alta frequência.

O Problema das Variáveis Globais (Membros)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
Para que ``is_still_reachable`` funcione sem receber todos os parâmetros novamente via XML (o que causaria overhead de comunicação), ela depende totalmente do **Estado Interno** salvo pela função ``find_best_base_position``.

Lógica de Execução (Fail-Fast):
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

1.  **Check de Sobrevivência:** Se ``selected_ik_position`` estiver vazio, retorna ``false`` imediatamente.
2.  **Validação 2D Instantânea:** Verifica se a posição *salva* da base foi invadida por um obstáculo dinâmico no mapa de custo (ex: uma pessoa andou até onde o robô ia parar).
3.  **Reconstrução de Cena:** Recria o ambiente MoveIt usando ``last_authorized_collision``.
4.  **Verificação Pontual:** Testa o IK apenas para a configuração salva.

Se esta função retornar ``false``, a Behavior Tree aborta a navegação imediatamente, permitindo que o robô recalcule uma nova rota antes de falhar fisicamente.
